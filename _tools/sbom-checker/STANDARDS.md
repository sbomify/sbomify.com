# Standards basis and assessment limits

The checker retains the platform's finding IDs, but published specifications take precedence over historical scoring parity. `test/cases.test.ts` runs every standard-derived case; no known discrepancies are skipped. `test/standards-regressions.test.ts` covers the 17 findings from the review of PR #180, including official-schema validation of the reproduction documents.

## Primary references

- [NTIA Minimum Elements, July 2021](https://www.ntia.gov/files/ntia/publications/sbom_minimum_elements_report.pdf): Data Fields and Depth.
- [CISA August 2025 public-comment draft](https://www.cisa.gov/sites/default/files/2025-08/2025_CISA_SBOM_Minimum_Elements.pdf): Data Fields and Coverage. This framework is explicitly a draft.
- [2026 Minimum Elements, official co-author publication](https://www.cyber.gov.au/publication/2026-minimum-elements-for-a-software-bill-of-materials-sbom): document fields, component fields and Validation.
- [BSI TR-03183-2 v2.1.0](https://www.bsi.bund.de/SharedDocs/Downloads/EN/BSI/Publications/TechGuidelines/TR03183/BSI-TR-03183-2_v2_1_0.pdf?__blob=publicationFile&v=3): §§3–6 and mapping Tables 8–11.
- [CycloneDX 1.6 JSON reference](https://cyclonedx.org/docs/1.6/json/): component nesting, dependencies, compositions, licenseChoice and acknowledgements.
- [SPDX 3.0.1 SpdxDocument](https://spdx.github.io/spdx-spec/v3.0.1/model/Core/Classes/SpdxDocument/) and its official JSON schema: embedded elements and inline objects.
- [SPDX 2.3.1 document information](https://spdx.github.io/spdx-spec/v2.3.1/document-creation-information/): §§6.5.2 and 6.6 distinguish document namespaces from physical download locations.
- [RFC 3339 §5.6](https://www.rfc-editor.org/rfc/rfc3339.html#section-5.6), [RFC 9557 §§3–4](https://www.rfc-editor.org/rfc/rfc9557.html#section-3), [RFC 3987 §2.2](https://www.rfc-editor.org/rfc/rfc3987.html#section-2.2), and [RFC 1950](https://www.rfc-editor.org/rfc/rfc1950.html) (ADLER32).

## What a result establishes

A schema pass establishes validity against the bundled JSON schema and its format checks. It does not establish SPDX SHACL/model conformance, graph referential integrity, build-time coverage, licence truth, author identity, cryptographic authenticity or legal compliance. The 55 framework findings assess the available document fields across supported CycloneDX, SPDX 2 and SPDX 3 representations.

Reduced BSI scope, externally referenced BOM content and detached evidence can require author context or separate artifacts. Those limits appear in findings instead of a claim of verified conformance. SPDX 2 fails BSI's format floor; its ancillary checks do not claim that SPDX 2 lacks filenames, licences or checksums.

Reference checks run only on request. CORS, opaque responses, unsupported digest algorithms, identifier-only namespaces and body/time limits can leave evidence unverified. The published-release catalogue is deliberately explicit and must be updated with schema support when adding releases.

The additional licence-expression parser is bundled only with this tool. Schema validators remain separate version-specific chunks, and other site pages do not load the checker. A production PageSpeed comparison requires a deployed preview; local build and bundle checks do not replace that comparison before merge.
