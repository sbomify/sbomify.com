SBOM generators

Four generators. The best one picked for you.

Each ecosystem gets the most accurate tool first, with automatic fallback to the next. The lower the priority number, the sooner it is tried.

cyclonedx-py

The native Python generator, and the most accurate for Python.

Python

Priority 10

cargo-cyclonedx

The native Rust generator, and the most accurate for Rust.

Rust

Priority 20

cdxgen

The broadest ecosystem support. The best choice for Java, Gradle and multi-language projects.

Python, JS, Java, Go, Rust, Ruby and 8 more

Priority 35

Syft

Anchore's comprehensive scanner, with CycloneDX and SPDX output, Terraform included.

Python, JS, Go, Terraform, Docker and 7 more

CycloneDX
The default. Versions 1.3 to 1.7, depending on the generator.
SBOM_FORMAT=cyclonedx
SPDX
Versions 2.2, 2.3 and 3.0.1, validated against the official schemas.
SBOM_FORMAT=spdx

Beyond SBOMs, the same pipeline uploads pre-authored VEX, CBOM and HBOM documents as they are, with BOM_TYPE=vex, cbom or hbom.

{{< comment >}}Enrichment: 12 sources, in the order they are tried{{< /comment >}}
Enrichment

12 data sources. Licences and suppliers, filled in.

Enrichment adds descriptions, licences, supplier details and lifecycle dates to your components, trying the fastest and most authoritative sources first.

  1. 1

    Pre-computed databases

    Local, with no network calls. Checked first.

    LicenseDB
    Licences for APK, DEB and RPM packages across 28 Linux distribution versions.
    Lifecycle Database
    Release, end-of-support and end-of-life dates (ECMA-428 CLE) for major runtimes and frameworks, from Python and Go to Django and Rails.
  2. 2

    Native registries

    Authoritative data from each ecosystem's official source.

    PyPI
    pkg:pypi
    crates.io
    pkg:cargo
    pub.dev
    pkg:pub
    Debian Sources
    pkg:deb/debian
    Conan Center
    pkg:conan
  3. 3

    Aggregators

    Broad coverage across ecosystems.

    deps.dev
    Google's open source dependency insights, covering most major ecosystems.
    Ecosyste.ms
    Community-driven package metadata and project health.
  4. 4

    Fallbacks

    When the others have no data.

    PURL extraction
    Maps package URL namespaces to suppliers, locally.
    ClearlyDefined
    Community-curated licence and metadata.
    Repology
    Package tracking across Linux distributions.

Turn it on in the action or the CLI with ENRICH=true or --enrich.

{{< comment >}}Augmentation: organisational metadata{{< /comment >}}
Augmentation

Your details on every SBOM. Without editing JSON.

Augmentation adds who made the software and where it came from, from three places.

  • {{< ph "buildings" >}}Your sbomify workspace: supplier, manufacturer, authors and declared licence.
  • {{< ph "file-code" >}}A local config: override the supplier, authors, licence and VCS details with an sbomify.json in your repository.
  • {{< ph "git-branch" >}}Your CI environment: the repository URL, commit SHA and branch, detected in GitHub Actions, GitLab CI and Bitbucket Pipelines.

Turn it on with AUGMENT=true or --augment.
