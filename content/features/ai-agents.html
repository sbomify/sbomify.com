The AI agent token

Built to propose. Not to decide.

Create a token in Settings with the AI agent scope. It belongs to the person who made it and can never do more than that person's role allows. Every request it makes is marked as coming from an agent, so reviewers always know what they are approving.

  • {{< ph "check-circle" >}}It can read your workspace and its vulnerabilities, pick up the fix and triage prompts, send VEX rulings for review, and draft and edit security advisories.
  • {{< ph "prohibit" >}}It cannot apply a ruling, approve or reject anything (its own work included), or publish, withdraw or delete an advisory. Those calls are refused.
  • {{< ph "git-pull-request" >}}After publishing, every change an agent sends to an advisory becomes a proposal, shown as a diff against the current text.

Human in the loop

Two jobs agents are good at. Both end with a person.

A ruling on a vulnerability feeds your VEX and your Trust Center. An advisory goes straight to customers. For both, sbomify holds what an agent sends until someone on your team signs off.

{{< ph "terminal-window" >}}

CVE triage

The agent reads the vulnerability in the context of your code and sends a ruling with its reasoning, such as not affected because the code is not reachable.

{{< ph "user-check" >}}

Approved into VEX

The ruling waits on the Review tab. Once a person approves it, sbomify writes it into the component's VEX. Rejected rulings change nothing.

{{< ph "siren" >}}

Security advisories

When a vulnerability does affect you, the agent drafts the advisory. A draft is visible only to your workspace, and only owners and admins can publish it.

{{< ph "git-pull-request" >}}

Changes as proposals

After publishing, a new update or an edited field from the agent arrives as a proposal with a diff. Approve it, reword it, or reject it with a reason the agent reads back.

MCP server

Plug in any MCP client. No glue code.

sbomify serves a Model Context Protocol endpoint at /mcp. Point Claude Code, Cursor or any other MCP client at it, and the agent sees tools for your products, components, releases, artifacts, vulnerabilities, assessments, advisories and CRA assessments.

  • {{< ph "key" >}}Scoped by the token. An agent is only shown the tools its token allows, and anything outside that scope is refused.
  • {{< ph "trash" >}}Nothing to delete with. No tool deletes anything, so “delete our SBOMs” has nothing to call.
  • {{< ph "stamp" >}}Publishing stays with people. Publishing advisories, changing visibility, approving submissions and signing declarations are never exposed to agents.
